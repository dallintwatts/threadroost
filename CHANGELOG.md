# Changelog

## Unreleased (2026-10-15)
- Ops (TR-OPS-2): far fewer Workers KV list calls, the free plan's scarcest operation (1,000 a day). Each 10-minute cron run lists handoffs once and shares that list between the abandoned sweep, renotify and alerts (was 3 lists). Live-sync threads are listed only while a small `courier:streams-active` key says one has unsent turns, plus one backstop run at the top of each hour (was every run). Ack deletes the chunk keys it already knows and lists only if a stray chunk past `total_chunks` exists (was a list on every ack). Measured in `test/kvlist.test.mjs`: idle cron 1 list (was 4), top of the hour 2, ack 0. When KV list fails (429 after the daily limit) nothing is deleted: sweep and renotify skip, `GET /api/handoffs` answers 503 `storage_list_limited` with `retry-after`, reading and acking a handoff by id still work, and the cron raises a `storage_list_limited` owner alert. Test-only `KV_TEST_HOOKS` setting counts lists and simulates the 429.
- Security (TR-SEC-3): new optional `COURIER_ADMIN_TOKEN` Worker secret. Once it is set, the pull token can only list, read and ack handoffs and read the owner alert. Pair codes, connect links and every other `/api/admin/*` route answer 403 `admin_token_required` to it, and the admin token keeps full access. Without the secret nothing changes. `/health` shows `admin_token_split`. To run `./setup.sh --doctor` webhook probes or mint a pair code after the split, point `--token-file` at a file holding the admin token. After the split, Connect and sign-in pages tell the owner to run `./setup.sh --pair` with the admin token instead of asking the bot for a new link (Bugbot, PR #7), and the inbox routine handles the 403.
- Eval (TR-EVAL-1): `npm run eval` files 28 synthetic handoffs end to end (local Worker + intake.py) in 3 trials and checks every turn's bytes, the injection cases' side effects, expiry and the alert path. CI runs it on every pull request.
- Fix (TR-BUG-36, first logged as TR-BUG-34, an id PR #1 already used): `intake.py drain --id ""` is refused as `invalid_handoff_id` instead of draining every pending handoff.
- Skill: trimmed the threadroost-intake skill wording to 23,849 bytes (151 under the 24,000 cap). Same rules, same id patterns, same intake.py (sha256 37128067f3b3).
- Alerts (TR-ALERT-1): the 10-minute cron sends your bot one `threadroost.alert` when a finished chat hasn't reached it within 30 minutes, or 3 or more webhooks in a row failed. It sends at most one an hour and doesn't repeat a delivered alert for the same problem within a day. The alert holds counts and ids only. The intake also reads `GET /api/admin/alert` on every catch-up run and shows each alert once in plain words, so alerts arrive even when webhooks are down.
- Isolation (TR-STATE-1): removed the per-isolate client-source cache and the cached OAuth provider (it kept the first request's env). The rate limiter evicts its oldest key instead of wiping every limit. A test pins the only two allowed in-memory maps.
- Added `.cursor/BUGBOT.md` review rules.
- Fix (TR-CI-6): removed a `worker/node_modules` symlink committed by mistake in ce31dab. It pointed a fresh clone's `npm ci` at a folder outside the clone. `.gitignore` now ignores `node_modules` as a file too, and a test checks it.
- Fix (TR-BUG-33): handoff_ready webhooks now carry `delivery_id` and `attempt`. The bot intake keeps a ledger keyed on handoff id plus delivery id, under a file lock. A repeat or re-claim of a handoff already filed returns `already_filed` with its path instead of logging a false duplicate, and re-acks with the original verdict when the first ack was lost.
- Security (TR-SEC-1): handoff text is treated as untrusted data in the inbox routine and the skill. Each turn is fenced in transcript.md so it cannot forge headings, and the intake refuses malformed handoff and delivery ids.
- Setup (TR-CI-1..4, clean-install test): a busy bot's HTTP 400 on the webhook test is retried once after 20 seconds, and a lasting failure shows the bot's reply and what to do next. README quick start shows the clone command, its INSTALL link points at step 3 again, and the rotate and remove lines match setup.sh.
- Landing: removed `Cache-Control: no-transform` so compression works again.

## 1.2.2 (2026-10-15)
- Fix (TR-BUG-32): Grok Bot can answer a webhook with HTTP 400 when its automation run rate limit is reached, not only when the inbox routine is paused. Threadroost now keeps a short redacted reply snippet (`response_snippet`) in handoff_status, probe-webhook and logs, retries a busy or transient failure once about 20 seconds after finish_handoff, and still re-notifies from the cron. Replies that say paused, deleted, not found or bad key are not retried early.
- The 400 hint now says the routine may be busy, paused or deleted and points to the snippet.
- New setting `WEBHOOK_RETRY_DELAY_MS` (default 20000, max 25000).

## 1.2.1 (2026-10-15)
- Cron re-notifies queued handoffs, first call after pairing gets one retry, finish re-checks a just-sent chunk, repeat acks keep their verdict, listing shows current statuses, plain-words webhook hints.
